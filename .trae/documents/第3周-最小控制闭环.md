# 第 3 周：最小控制闭环（TAP / SCROLL / BACK）

## Context

TrackLink 的第 1 周（触控板 Raw Input 可行性）与第 2 周（蓝牙 RFCOMM 链路）已完成并真机验证：Windows `serve` 与 Redmi K20 Pro 之间同一会话 719 秒不掉线、RTT 中位 31 ms，MVP 的「连续 10 分钟不掉线」已达标。

但**手机端至今不会执行任何操作**——`BluetoothConnectionManager.handle()` 只处理 HELLO/PING/PONG，`FrameType` 里也只定义了这三种帧。也就是说整条链路的最后一环（`AccessibilityService` → `dispatchGesture()` / `performGlobalAction()`）是本项目唯一**从未验证过**的部分。

本周目标：让「触控板输入 → 蓝牙命令 → 手机真的点/滚/返回」跑通，对应计划书的「第 3 周：最小控制闭环」。

### 已确认的取舍（用户选定）

1. **加「无障碍自测」面板**：先用 App 内本地按钮独立验通无障碍层，再接线蓝牙。
2. **直接接触控板手势识别**：不插入键盘热键中间步骤；Windows 端靠控制台日志观察识别结果来分层排查。
3. **TAP 用触控板绝对坐标映射**（归一化 0–65535），不做「固定屏幕中心」。

## 一、协议扩展（两端必须逐字节一致）

帧头不变：`[magic:2B 'T','L'][version:1B=0x01][type:1B][sequence:4B LE][length:2B LE][payload]`。

在 [Protocol.cs](file:///d:/Code/Projects/TrackLink/TrackLink.Windows/Bluetooth/Protocol.cs#L7-L12) 与 [Protocol.kt](file:///d:/Code/Projects/TrackLink/TrackLink.Android/app/src/main/java/com/tracklink/remote/bluetooth/Protocol.kt#L11-L25) 同步新增：

| 类型 | 值 | payload（小端） | 说明 |
|---|---|---|---|
| `Tap` | `0x10` | `x:u16, y:u16`（4B） | 归一化 0–65535 |
| `Scroll` | `0x11` | `dx:i16, dy:i16`（4B） | ±32767 ≈ 一屏高/宽 |
| `Global` | `0x12` | `action:u8`（1B） | 1=BACK, 2=HOME, 3=RECENTS |
| `Stop` | `0x1F` | 无 | 保留，本周仅定义不实现 |

沿用现有常量 `HeaderLength=10` / `MaxPayload=1024`。

两端的解析器对未知类型都已能保持同步（Windows 会打印「忽略未知类型」；Android 的 `FrameType.of()` 返回 null 时仍 `discard(HEADER_LENGTH + payloadLength)`），因此**先各自升级单端不会互相污染**。

## 二、Android 端改动

### 新增 `accessibility/` 包

**`TrackLinkAccessibilityService.kt`**
- 继承 `AccessibilityService`，实现 `canPerformGestures`。
- `onServiceConnected()` 把自己注册进 `GestureDispatcher`；`onDestroy()` 注销。
- `onAccessibilityEvent()` 空实现；`onInterrupt()` 通知派发器清空队列（系统会自行取消进行中的手势）。

**`GestureCommand.kt`**
```kotlin
sealed interface GestureCommand {
    data class Tap(val x: Int, val y: Int) : GestureCommand          // 归一化 0..65535
    data class Scroll(val dx: Int, val dy: Int) : GestureCommand     // 归一化 i16
    data class Global(val action: Int) : GestureCommand              //
}
```

**`GestureDispatcher.kt`**（进程级单例 object，负责**串行执行**）
- `Channel<GestureCommand>(Channel.UNLIMITED)` + **单个**消费协程跑在 `Dispatchers.Main.immediate`。单消费者 + await 上一条完成，即为计划书要求的「单一串行队列」，无需引入实验性 API。
- `awaitGesture(desc)` = `suspendCancellableCoroutine` 包 `dispatchGesture`，在 `onCompleted`/`onCancelled` 恢复；外层套 `withTimeout(duration + 500ms)`，保证 `onInterrupt` 后队列能自愈。
- `submit(cmd)`：服务未启用时丢弃并写日志（对应测试清单的「无障碍服务被关闭后拒绝执行并提示用户」）。
- 屏幕尺寸取 `service.resources.displayMetrics`；坐标 `px = v / 65535f * widthPx`（`y` 同理，用 `heightPx`）。
- `log: ((String) -> Unit)?` 回调，把「收到 TAP(0.52,0.31) → 已派发」这类信息送回 UI 日志区，作为延迟取证。
- 手势细节：TAP = `moveTo(x,y)` 后接一个极短 `lineTo(x+1f, y+1f)`（规避 `GestureDescription` 对空笔画的校验），`duration = 50ms`；SCROLL = 从屏幕中心 `(cx, cy)` 沿主轴滑 `dy/32767f * heightPx`（`dx` 走横向），`duration = 200ms`；Global 走 `performGlobalAction(GLOBAL_ACTION_BACK/HOME/RECENTS)`。

## 三、Windows 端改动

### 复用第 1 周已验证的输入层

从 [TrackLink.Windows.Spike](file:///d:/Code/Projects/TrackLink/TrackLink.Windows.Spike) 移植（该工程是控制台 Exe，未做项目引用，按文件移植）：

- `NativeInterop.cs` → `Input/RawInputNative.cs`：只取 `RegisterClassEx` / `CreateWindowEx`(HWND_MESSAGE) / `RegisterRawInputDevices` / `GetRawInputData` / `GetRawInputDeviceList` / `GetRawInputDeviceInfo` / `DefWindowProc` / `PeekMessage` / `DispatchMessage` 及相关结构体与常量。
- `HidDecoder.cs` → `Input/HidTouchpadDecoder.cs`：`TouchpadDecoder` 的能力表读取、`HidP_GetData` + `BuildDataIndexMap` 解码路径**原样保留**（`HidP_GetUsageValue` 在本机 ELAN 上必失败，这条路径不能改）。`Decode()` 目前只返回字符串，需**新增结构化方法** `TryDecode(byte[] report, out TouchReport)` 输出 `CC / CID[] / TIP[] / BTN / X[] / Y[]`。
- `Program.cs` 的 `GroupKey()`、`BuildEntry()`、`EnumerateDevices()` 触控板判定逻辑 → `Input/TouchpadCatalog.cs`。

### 新增 `Input/` 其余文件

- **`RawInputListener.cs`**：建 `HWND_MESSAGE` 消息窗口，只注册 `0x0D/0x05`（触控板多触点集合，用 `RIDEV_INPUTSINK`），在**独立线程**泵消息，按分组键过滤后抛 `TouchReport` 事件。外部鼠标分组键不同，天然被排除（对应验收项「外接鼠标不影响手机」）。
- **`GestureRecognizer.cs`**：按第 1 周的硬结论做**帧聚合**——`CC>0` 开启一帧，随后依 `CID` 累积各接触点（后续报文 `CC=0`），直到 `TIP` 全部释放才算一帧结束。判定规则：
  - `maxContacts==1` 且位移 < 8% 屏宽/高 且时长 < 300 ms → **TAP**
  - 出现 `0x09/0x01` 物理按键置位 → **TAP**（坐标取按下时刻的接触点，无接触点时用中心）
  - `maxContacts==2` 且 `|dy| > |dx|` 且 `|dy| > 10%` → **SCROLL**
  - `maxContacts==3` 且 `dx < -15%` → **BACK**
  - 判定成功后 200 ms 冷却，防抖动重复触发。
- **坐标归一化**：用能力表中 `0x01/0x30`(X) 与 `0x01/0x31`(Y) 的 `LogicalMin/LogicalMax`；若 `LogicalMax <= LogicalMin` 则回退到第 1 周实测范围 `X 0..3864 / Y 0..2499`，并在日志中标注走了回退分支。
- **`RemoteCommand.cs`**：命令 + 上述 payload 编码。

### 打通发送路径

当前会话是 [RfcommHost.AcceptLoop](file:///d:/Code/Projects/TrackLink/TrackLink.Windows/Bluetooth/RfcommHost.cs#L152-L153) 里的 `using var session` 局部变量，输入层拿不到。改动：

- [BtSession.cs](file:///d:/Code/Projects/TrackLink/TrackLink.Windows/Bluetooth/BtSession.cs#L136-L159)：`private void Send` → `public bool Send`（返回值表示是否真的写出去），线程安全已由 `_sendLock` + `_closed` 保证，无需新增同步。
- [RfcommHost.cs](file:///d:/Code/Projects/TrackLink/TrackLink.Windows/Bluetooth/RfcommHost.cs#L135-L167)：加 `public BtSession? CurrentSession { get; }` 与 `event Action<BtSession?>? SessionChanged`，在 `Run()` 前后置位/清空。
- [Program.cs](file:///d:/Code/Projects/TrackLink/TrackLink.Windows/Program.cs#L27-L34)：新增 `remote` 模式 = 启动 RFCOMM 服务端 + 启动触控板监听 + 把手势命令发给 `CurrentSession`。控制台打印：识别到的触控板分组键、归一化范围来源（caps / 回退）、每条识别出的命令与发送时刻。`serve` 保持不变，用于纯链路测试。

## 四、验证步骤

**A. 无障碍层独立验证（先做，风险最高）**
1. 构建安装：`gradle assembleDebug` → `adb install -r` → `am start`（MIUI 需已开「USB 安装」+「USB 调试（安全设置）」）。
2. 手机设置里手动启用 TrackLink 无障碍服务；回 App 确认状态卡片变「已启用」。
3. 逐一人工点自测面板的 4 个按钮，确认手机真的「点了屏幕中心 / 列表滚动了 / 回到了上一页 / 回到桌面」。
4. 取证：`adb shell screencap -p /sdcard/x.png` + `adb pull`（**不可用 PowerShell `>` 重定向，会写成 UTF-16 破坏 PNG**）；MIUI 拦截 `adb shell input tap`，按钮只能人工点。

**B. 端到端**
5. Windows 跑 `remote` 模式，确认日志打印触控板分组键与归一化范围来源；确认手机连上后 `SessionChanged` 有会话。
6. 逐项验证：单指轻点 → 在浏览器网页里点中链接；两指上下滑 → 列表滚动；三指左滑 → 返回上一页；物理按压触控板 → 点击。同时观察 Windows 日志里识别出的命令是否与动作一致（用来区分「手势判定错」还是「协议/执行错」）。

**C. 指标与回归**
7. 延迟：比对 Windows 的「发送时刻」与手机日志里的「收到 → 已派发」，确认「手势结束 → 手机开始执行」< 100 ms（第 2 周 RTT 中位 31 ms，余量充足）。
8. 外接鼠标：移动 + 点击外接鼠标，确认手机无任何反应、Windows 无命令打印。
9. 关闭无障碍服务后再触发手势，确认被拒绝且有明确提示、不崩溃。

**D. 收尾**
10. 把第 3 周结果（协议表、手势阈值、实测延迟、踩到的坑）回写 [TrackLink-纯软件项目计划.md](file:///d:/Code/Projects/TrackLink/TrackLink-纯软件项目计划.md#L309-L313)。
